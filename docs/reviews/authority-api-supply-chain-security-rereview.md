# Re-review of the authority, API and supply chain fixes

- Reviewer: the security specialist, working independently. I wrote none of the fixes and none of the three reviews. I changed no product code. My additions are this document and four new test targets.
- Date: 2026-10-29. Reviewed commit: `4c11489` (`feat/slice-0-foundation`, "Merge the authority review fixes and the worker pipeline assembly"; the worktree was fast-forwarded from `119607d`).
- Question: do the fixes of `supply-chain-and-delivery-security-review.md`, `api-security-review.md` and `authority-and-evidence-security-review.md` hold when attacked with other inputs than the ones their authors used, and what did the fixes miss.
- Environment: one macOS laptop, cargo 1.98.0, PostgreSQL 18 from Homebrew started by the storage crate's test support, the testkit's fake GitHub on the loopback interface, the real policy files, the real engine. No real GitHub, no deployment, no Docker, no model calls, no network beyond loopback.
- Evidence: 45 tests in four new targets. **22 are confirmed defects and fail today; they are `#[ignore]`d so CI is unchanged. 23 are probes that held; those that need no database run in the normal suite.** No `[[test]]` line was needed and no existing file was edited. The earlier reviewers' targets (`authority_security_review`, `supply_chain_review`, `security_review` of the GitHub crate, `approval_security_review`) and the suites `supply_chain` (90), `dependency_decision` (14) and `override_policy` (4) were rerun and pass, except `aut_5_...` (see section 3).
- Checks run: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo xtask check-architecture` pass. The secret scan result is in section 9.

## 6. What held, in one place

- The MAC: no field is outside it, and nothing outside it matters to an effect. An old record, a record of another tenant and a record for another verb or job are refused. Errors and markers never carry the expected word.
- The audit table and the login: no update, delete or truncate of an audit row by the API login; no privilege beyond four inserts; no read of server files; no program; no role change.
- Tenancy of idempotency keys and of decisions, base binding, moved head, and the approval invalidation reason.
- The text sent to GitHub: images and foreign links in every shape I tried, raw HTML, fences, quotes, tables, invisible characters. Allowed hosts are matched by suffix with a dot.
- Redirects are off in the GitHub transport; a transferred issue is an error.
- The command parsers' handling of quotes, fences, comments, second lines and names that are not package names.
- The 90 + 60 + 14 + 4 tests of the supply chain and override suites.
